# Регламент валидации и контроля целостности (06_validation.md)

## 📌 Назначение модуля
Скрипт `scripts/verify_integrity.py` обеспечивает автоматический контроль качества и валидацию данных перед каждой публикацией сайта или после парсинга новых демок.

---

## 🔍 Ключевые блоки проверок

### 1. Валидация базы данных (`test_data`)
- **Формат Steam ID**: Проверка всех ключей в `data/players_db.json` и `data/players/*.json` на отсутствие float-нотаций (например, `7.656e+16`) и невалидных значений (`None`, `NaN`, `0`).
- **Связность матчей**: Каждый матч в `data/matches/*.json` обязан иметь корректный `match_id`, дату, карту, 10 валидных участников и валидный счет раундов.
- **Реестр демок**: Наличие и валидный синтаксис `data/registry.json`.

### 2. Валидация интеграции FACEIT (`test_faceit`)
- Проверка структуры файлов кэша в `data/faceit/*.json`.
- Проверка наличия всех 11 векторных SVG бейджей (`site/icons/faceit/level_{0..10}.svg`).
- Тестирование безопасного fallback: система обязана возвращать Exit Code 0 даже при отсутствии ключа `FACEIT_API_KEY`.

### 3. Валидация статического сайта (`test_site`)
- **Наличие ключевых страниц**:
  - `site/index.html` (Главный дашборд)
  - `site/matchmaker.html` (Балансировщик 5v5)
  - `site/compare.html` (Бойцовский клуб 1v1)
  - Страницы всех матчей `site/matches/{match_id}.html`
  - Профили всех игроков `site/players/{steam_id}.html`
  - Отчеты игровых сессий `site/sessions/{date}.html`
- **Проверка шаблонизатора (Jinja2 Leakage)**:
  В сгенерированных HTML-файлах не должно оставаться нераспарсенных тегов `{{` или `{%`.
- **Проверка ссылок (Relative Paths)**:
  Все пути к стилям (`css/style.css`), скриптам (`js/app.js`), иконкам и внутренним ссылкам должны быть строго относительными (`./`, `../`), чтобы сайт корректно работал на любом хостинге и в подкаталогах GitHub Pages.

---

## 🚀 Команды для проверки
```powershell
# Запуск сквозной проверки целостности
python run.py --stage verify

# Прямой вызов проверочного модуля
python scripts/verify_integrity.py
```
При успешном прохождении всех тестов скрипт завершается со статусом `EXIT CODE 0` и сводным отчетом с зелеными индикаторами `[OK]`.
